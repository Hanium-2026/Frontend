# NEVO 화면 명세 — 디자인 브리프

> **용도**: 이 문서 하나만 읽고 앱 전체 화면을 디자인할 수 있게 쓴 명세다.
> 모든 데이터 항목은 **실제 백엔드 DTO에서 확인한 것**이고, 없는 것은 «없다»고 명시했다.
> 최종 확인: 2026-08-20 (Backend `develop` 브랜치 DTO 직접 대조)

---

## 0. 제품 한 줄 정의

**스마트폰을 주머니에 넣고 걷기만 하면, 파킨슨·뇌졸중 같은 퇴행성 뇌질환의 초기 보행 변화를 일상에서 찾아내는 앱.**

- 분석은 **휴대폰 안에서** 끝난다(on-device AI). 서버는 결과 저장·리포트·알림만 한다.
- 사용자는 **어르신(WARD)** 과 **보호자(GUARDIAN)** 둘. 한 사람이 둘 다일 수 없다.
- **Android 전용**. iOS·웹·태블릿 없음.

### 가장 중요한 전제 — 상시 측정 앱이다

**사용자가 버튼을 눌러 30초 재는 앱이 아니다.** 백그라운드에서 하루 종일 걸음을 모은다.
디자인은 이 전제를 따른다.

| | 세션 방식이라면 | **상시 측정(우리)** |
|---|---|---|
| 홈의 성격 | 「측정 시작」이 주인공 | **쌓인 결과를 보는 대시보드** |
| 주요 행동 | 측정 버튼 | **없음** — 확인이 목적 |
| 데이터 부족 | 측정 실패 | **활동량 저하** — 그 자체로 정보 |
| 참고 모델 | Nike Run Club | **Apple Health · 삼성헬스** |

> 삼성헬스 홈 스크린샷을 확인한 결과 **측정 CTA가 하나도 없었다.** 전부 이미 쌓인 것을 보여주는 카드다.

⚠️ 현재 구현은 아직 포그라운드 세션 방식이다. **디자인은 목표를 따르고, 코드가 따라온다.**

## 1. 사용자

### WARD — 어르신
- 60~80대. 시력·색 변별력·손떨림을 전제한다.
- **본문 17px 이상, 캡션 14px 이상.** 9~13px 본문 금지. 터치 영역 최소 56px.
- 앱 전체에 **글씨 크기 4단계** 접근성 설정이 있다 → 글자가 커져도 레이아웃이 깨지면 안 된다.
- 한국어. 한글은 영문보다 글자 폭이 넓고 줄바꿈 규칙이 달라, **영문 목업으로 검증되지 않는다.**

### GUARDIAN — 보호자
- 30~50대 자녀. 정보 밀도를 높여도 된다.
- 관심사는 하나다: **«오늘 부모님 괜찮으신가».**

## 2. 백엔드가 주는 것 (진실의 원천)

디자인에 없는 데이터를 그리면 안 된다. 아래가 전부다.

### 사용자
| 항목 | 값 |
|---|---|
| `/users/me` | `id`, `phone`, `name`, `role` |
| 신체정보(WARD만) | `height`, `weight`, `birthDate`, `gender` |

> ⚠️ **이메일·프로필 사진·주소·생년월일 외 개인정보는 없다.** 아바타는 이름 이니셜로 만든다.
> `gender`는 `MALE`/`FEMALE` 둘뿐이다.

### 보행 데이터
| 항목 | 범위 | 의미 |
|---|---|---|
| `avgScore` / `minScore` / `maxScore` | 0~100 | 걸음 건강 점수. **높을수록 좋다** |
| `riskLevel` | `NORMAL` / `SUSPECTED` | **2단계뿐** |
| `dangerCount` | 정수 | 위험 신호 횟수 |
| `variabilityScore` | % | 걸음 간격이 얼마나 들쭉날쭉한가. **낮을수록 좋다** |
| `symmetryScore` | 0~100 | 좌우 균형. **100에 가까울수록 좋다** |
| `sessionCount` | 정수 | 그날 보행 횟수 |

**UI 위험도는 3단계로 표시한다** (점수<50 위험 · SUSPECTED거나 50~69 주의 · 그 외 안정).
백엔드 2단계 → UI 3단계 변환은 앱이 한다.

### 알림
**종류가 `STROKE_DANGER` 하나뿐이다.** 알림 유형별 필터·분류·아이콘 구분이 필요 없다.
필드는 `alertId`, `type`, `sessionId`, `message`, `createdAt`.

### 위치
`latitude`, `longitude`, `recordedAt`. 실시간 스트림(SSE)으로 온다.

## 3. 백엔드에 **없는** 것 — 그리지 말 것

과거에 이런 더미 화면들이 있었고 전부 제거했다. **동작하지 않는 토글·버튼·수치를 있는 것처럼 그리면 안 된다.**

- ❌ 알림 설정 (시간대·종류별 on/off)
- ❌ 공유 설정 (누구에게 무엇을 보여줄지)
- ❌ 낙상 감지 · 지오펜스(안전구역 이탈)
- ❌ PDF 리포트 내보내기 · 119 자동 신고
- ❌ 걸음 수 / 이동 거리 **누적 기록** (측정 중 실시간 표시만 있고 저장되지 않는다)
- ❌ 프로필 사진 업로드
- ❌ 오늘 동선(경로) — *백엔드 대기 중. 현재는 «현재 위치» 한 점만 있다*

### 알아둘 함정 두 가지

**① 보고서 문구(`reportSummary`)는 항상 비어 있다.** 앱이 안 보내서 서버에 늘 `null`이다.
결과 화면의 설명 문구는 **위험도별 고정 문장**이다. 「AI가 분석한 요약」처럼 표기하면 거짓말이 된다.

**② 어르신용과 보호자용 7일 데이터의 모양이 다르다.**

| API | 빈 날 |
|---|---|
| 보호자 대시보드 `trend` | **항상 7칸, 없는 날은 `null`** |
| 어르신 7일 리포트 `dailyScores` | **기록 있는 날만 온다** (빈 날이 빠진 채로 옴) |

→ 어르신 쪽은 앱이 날짜로 채워 넣는다. **디자인은 양쪽 다 «빈 날이 빈 칸으로 보이는» 차트여야 한다.**
빈 날을 압축하면 월·수·금이 연속 3일처럼 보여 거짓 정보가 된다.

## 5. 핵심 화면 상세

### ① WARD 홈 — 「오늘 나 괜찮은가」

가장 중요한 화면. 어르신이 하루에 한 번 열고 **3초 안에** 답을 얻어야 한다.

**반드시 있어야 할 것**

| 요소 | 데이터 | 비고 |
|---|---|---|
| 인사 | `name` | 「홍길동님, 안녕하세요」 |
| **오늘 점수** | 오늘 `avgScore` | **화면의 주인공.** 가장 큰 요소 |
| 상태 칩 | 점수 → 안정/주의/위험 | **색을 지닌 유일한 요소** |
| 어제 대비 | 오늘 − 어제 | 「어제보다 3점 높아요」 |
| 오늘 요약 | `sessionCount`, `minScore`~`maxScore` | 「보행 3번 · 점수 62~91」 |
| 7일 추이 | `dailyScores` | **선 차트** (아래 6장) |
| 보호자 | 연결된 보호자 이름·수 | 없으면 「연결하기」 |
| 긴급 | — | **스크롤 밖 고정** |

**설계 원칙**

- **점수 범위(최저~최고)가 평균만큼 중요하다.** 평균 80인데 최저 45면 그게 신호다.
- **색 운반체는 하나.** 점수 숫자는 검정, 상태 칩만 색을 갖는다. 둘 다 초록이면 같은 말을 두 번 한다.
- **같은 값을 두 번 보여주지 않는다.** (삼성헬스 홈이 걸음 수를 두 번 보여주는 것이 나쁜 예)
- **좌우 대칭·변동성은 홈에 넣지 않는다.** 어르신이 「좌우 대칭 87%」로 취할 행동이 없다.
- **측정 CTA는 주인공이 아니다.** 작은 카드 하나로 충분하다(상시 측정이므로).
- 숫자 카운트업 애니메이션 금지 — 값이 확정될 때까지 못 읽는다.

**오늘 데이터가 없을 때** — 「오늘은 아직 걸음이 모이지 않았어요」. *실패가 아니라 «활동량 저하»로 다룬다.*
**기록이 아예 없을 때** — 「아직 기록이 없어요 / 걸으시면 여기에 쌓여요」

### ② WARD 측정 — 「지금 걷는 중」

걷는 동안 켜 두는 화면. **주머니에 넣고 걷기 때문에 대부분 안 본다.** 걷기 전후에 본다.

**반드시 있어야 할 것**

| 요소 | 비고 |
|---|---|
| 현재 점수 | 큰 숫자 |
| 현재 상태 | 정상 보행 / 이상 의심 / 정지 |
| 측정 시간 | mm:ss |
| **기록까지 남은 시간** | ★ 아래 참고 |
| 걸음 수 | 「제대로 세고 있다」는 신호 |
| 점수 추이 | 실시간 그래프 |
| 완료 버튼 | 크게, 하단 고정 |

**★ 「기록까지 남은 시간」이 이 화면의 핵심이다**

걸음이 부족한 측정(약 15초 미만)은 **기록되지 않는다.** 몇 걸음짜리 점수가 하루 평균을
오염시키기 때문이다. 그런데 그냥 버리면 사용자는 「측정했는데 기록에 없다」고 혼란스러워한다.

→ **저장 시점이 아니라 걷는 동안 미리 알린다.**

```
걷기 전   「주머니에 넣고 평소처럼 걸어주세요」
걷는 중   「약 8초 더 걸으면 기록돼요」      ← 실시간으로 줄어든다
충족되면  「충분히 걸으셨어요. 완료를 눌러도 돼요」
```

완료를 눌렀는데 부족하면 → 「아직 기록되지 않아요 / 약 6초만 더 걸으면 기록할 수 있어요」
+ 〈더 걸을게요〉 〈기록 없이 종료〉

**하지 말 것** — 이동 거리 표시(걸음×키로 추정한 추정값이라 부정확하고 의미도 없다).

### ③ 측정 결과 — 어르신·보호자 공용 ⚠️

**한 화면이 세 곳에서 열린다.**

| 진입 | 데이터 출처 |
|---|---|
| 측정 직후 (어르신) | 방금 측정한 로컬 결과 |
| 기록에서 (어르신) | 서버 |
| 알림에서 (**보호자**) | 서버 |

⚠️ **보호자도 보는 화면이므로 어르신 전용 요소(하단 탭바 등)를 항상 띄우면 안 된다.**

**반드시 있어야 할 것**

| 요소 | 데이터 |
|---|---|
| 측정 시각 | 「8월 20일 14:32」 |
| **걸음 건강 점수** | `avgScore` — 주인공 |
| 상태 칩 | 안정/주의/위험 |
| 설명 문구 | 위험도별 고정 문장 (**«AI 요약»이라 부르지 말 것**) |
| 점수 범위 | `minScore`~`maxScore` |
| 좌우 대칭 | `symmetryScore` % |
| 변동성 | `variabilityScore` % |
| 위험 횟수 | `dangerCount` 회 |
| 공유 | 문자·카톡으로 내보내기 |

**설계 원칙**

- **평균 점수를 위에 크게 보여줬으면 아래 타일에 또 넣지 않는다.**
- 좌우 대칭·변동성은 **「함께 관찰된 보행 특성」**이지 점수의 근거가 아니다.
  점수는 AI 모델이 파형에서 직접 판정한다. 근거처럼 표현하면 거짓말이다.
- 짧은 측정이면 「걸음이 적어서 이번 측정은 기록에 남지 않았어요」를 명시한다.
- 좌우 대칭·변동성은 **`--`로 비어 있을 수 있다**(걸음이 8보 미만이면 계산 불가). 빈 값 디자인 필요.

### ④ WARD 기록 — 「지난 일주일 어땠나」

**반드시 있어야 할 것**

| 요소 | 데이터 |
|---|---|
| 7일 평균 | + 기간 내 변화(▲▼) |
| **7일 추이 차트** | 선 + **최저~최고 범위 밴드** |
| 기간 요약 | 측정 횟수 · 점수 범위 · 위험 신호 |
| 세션 목록 | 시각 · 점수 · 위험도 칩 · 좌우 대칭 |

**범위 밴드가 임상적으로 중요하다** — 파킨슨·뇌졸중 보행은 평균이 떨어지기 **전에 흔들림이 먼저** 나타난다.
그날의 최저~최고를 띠로 깔면 «수준»과 «변동»을 한 그림에서 읽는다.

### ⑤ WARD 보호자 — 목록 + 연결

**반드시 있어야 할 것**
- 연결된 보호자 목록 (이니셜 아바타 · 이름 · 연결일)
- 「보호자와 연결하기」 → **하단 시트**(별도 화면 아님)

**연결 방식** — 어르신이 보호자 전화번호를 넣어 **6자리 코드**를 만들고, 보호자가 그 코드를 입력한다.
시트 안에 ①전화번호 입력 ②생성된 코드(크게) + 만료 시각 ③3단계 안내가 모두 있어야 한다.

⚠️ **코드는 숫자가 아니라 영문 대문자 + 숫자 6자리다** (`K7P2M9` 형태).
혼동되는 `I` `O` `0` `1`은 백엔드가 이미 제외했지만, **어르신이 눈으로 읽어 전화로 불러주는 값**이므로
글자를 넉넉히 띄우고(자간) 크게 보여줘야 한다. 손글씨체·장식체 금지.

⚠️ 시트에 입력창이 있으므로 **키보드가 버튼을 가리지 않아야 한다.**

---

### ⑥ GUARDIAN 대시보드 — 「부모님 오늘 어떠신가」

보호자가 앱을 여는 유일한 이유. **여러 명을 등록할 수 있다.**

**어르신 카드마다**

| 요소 | 데이터 |
|---|---|
| 이름 | `name` |
| **최근 점수** | `latestScore` |
| 상태 칩 | `riskLevel` → 안정/주의/위험 |
| 마지막 측정 | `lastSessionAt` (「2시간 전」) |
| 7일 스파크라인 | `trend` (**7칸 고정, 없는 날 `null`**) |

**설계 원칙**
- **위험한 어르신이 맨 위로 올라와야 한다.** 안정 상태 3명 사이에 위험 1명이 묻히면 실패다.
- **「마지막 측정」이 점수만큼 중요하다.** 3일째 측정이 없으면 그것 자체가 신호다.
- 스파크라인의 **빈 날을 압축하지 말 것**(위 2장 참고).
- 어르신이 0명일 때 = 첫 사용자다. 연결 유도가 화면의 전부여야 한다.

---

### ⑦ GUARDIAN 어르신 상세

**반드시 있어야 할 것**
- 오늘 지표: 평균/최저/최고 · 좌우 대칭 · 변동성 · 측정 횟수 · 위험 신호
- 기간 전환 **7일 / 30일 / 90일** ← 어르신 화면에는 없는 기능
- 기간 추이 차트
- 세션 목록 → 측정 결과로 이동

여기는 정보 밀도를 높여도 된다. **의료진에게 보여줄 수 있는 수준**을 목표로 한다.

---

### ⑧ GUARDIAN 알림

**종류가 하나뿐이다**(`STROKE_DANGER`) — 필터·분류 UI 불필요.

- 알림 목록: 메시지 · 시각 · 어르신 이름
- **탭하면 해당 측정 결과로 이동** (`sessionId`)
- 빈 상태: 「아직 알림이 없어요」는 **좋은 소식**이다. 부정적으로 그리지 말 것.

---

### ⑨ GUARDIAN 위치

- 지도 + 어르신 현재 위치 한 점
- 실시간 수신 여부 표시 (「수신 중」/「대기」)
- 마지막 수신 시각

⚠️ **오늘 동선(경로)은 백엔드가 아직 없다.** 현재는 **현재 위치 한 점**만 가능하다.
동선 UI를 그리려면 «나중에 붙을 것»으로 명시할 것.

---

### ⑩ WARD 긴급(SOS)

- 큰 버튼 하나. **오작동 방지를 위해 길게 누르기**(0.9초). 누르는 동안 진행 상태가 보여야 한다.
- 누르면 보호자에게 **현재 위치 전송**
- 연결된 보호자가 없으면 그 사실을 먼저 알려야 한다

⚠️ **119 자동 신고 기능은 없다.** 있는 것처럼 표기하면 안 된다(과거에 이 허위 표기가 있었고 제거했다).

---

### ⑪ 나머지 WARD 화면

| 화면 | 반드시 있어야 할 것 |
|---|---|
| 내 정보 | 이름 · 전화 · 성별 · 나이 · 키 · 몸무게 / 가이드·개인정보·앱설정·로그아웃 진입 |
| 내 정보 수정 | 키·몸무게·생년·성별 폼. **저장 버튼이 시스템 내비게이션에 가리지 않을 것** |
| 앱 설정 | **글씨 크기 4단계** — 미리보기가 즉시 바뀌어야 한다 |
| 이용 가이드 | 측정 3단계(주머니→걷기→점수) + 앱 사용법 + 「휴대폰 안에서만 분석」 |
| 개인정보 보호 | 수집·이용 고지. **on-device 분석**이 신뢰의 핵심이므로 강조 |
| 온보딩 | 최초 1회. 앱 소개 · 상시 측정 안내 · 기기 내 분석 |

## 6. 디자인 시스템

### 색 — 3원칙

1. **무채색이 지면, 색은 신호.** 넓은 면적을 색으로 칠하지 않는다. 예외는 화면당 하나뿐인 주요 버튼.
2. **화면당 주인공은 하나.** 큰 요소가 여럿이면 위계가 무너진다.
3. **크기로 위계, 색으로 신호.**

| 역할 | 값 | 용도 |
|---|---|---|
| 액센트 | `#1B4F9C` | 임상 블루. 채도를 낮춰 넓게 써도 덜 튄다 |
| 안정 | `#0F7A5F` / 배경 `#E4F1EC` | |
| 주의 | `#A96A00` / 배경 `#F7EEDC` | |
| 위험 | `#B3312A` / 배경 `#F7E9E8` | |
| 글자 | `#10161D` 제목 · `#3C4753` 본문 · `#6B7885` 라벨 | |
| 지면 | `#F4F6F8` 배경 · `#FFFFFF` 카드 | |

**의미색은 위험도 3단계 전용이다.** 카테고리 구분용으로 늘리지 말 것.

**상태는 «칩»으로 표시한다** — 색 글자만 쓰면 획 두께만큼만 색이 보여 노년층이 구별하기 어렵다.
칩은 옅은 배경으로 **색을 면(面)으로** 전달한다. (모서리 8px 사각 칩. 알약 모양 아님)

### 타이포 — 노인 친화 5단계

| 이름 | 크기 | 용도 |
|---|---|---|
| display | 44 | 큰 점수 — **화면당 하나** |
| title | 26 | 화면 제목 |
| h | 20 | 카드 제목 |
| body | 17 | **본문 최소** |
| caption | 14 | **캡션 최소** |

사이를 비워 위계를 만든다. **15·16px 같은 중간값을 쓰지 않는다.**
글꼴은 Pretendard. 굵기는 Regular / Medium / SemiBold / Bold / ExtraBold.

### 간격·형태
- 간격 8의 배수. **어르신 화면은 한 단계 위를 기본으로** (카드 안 24, 카드 사이 16)
- 모서리 8 / 12 / 카드 18
- 터치 최소 **56px**
- 카드는 그림자가 아니라 **배경과의 명도 차이**로 구분한다

### 차트

**일별 점수에 막대를 쓰지 않는다. 선이다.**

| 문제 | 막대 | 선 |
|---|---|---|
| 실제 점수대(60~95) | 0부터 그려 74와 81이 거의 같아 보인다 | 구간만 그려도 정직 |
| 기록 없는 날 | 높이 0 = 0점과 구분 불가 | **선이 끊긴다** |
| 하루 안 변동 | 표현 못 함 | **범위 밴드**로 가능 |

- **y축 0~100 고정.** 70(주의 경계)에 옅은 임계선. 「78점」이 척도 어디쯤인지가 정보다.
- 점 지름 8px 이상. 얇은 선(2px), 옅은 격자.
- **모든 데이터 점에 숫자를 붙이지 않는다.**

## 7. 실기기에서 확인된 함정

디자인 단계에서 알고 있어야 할 것들.

| 함정 | 내용 |
|---|---|
| **하단 내비게이션 바** | 안드로이드 시스템 바가 화면 하단 버튼을 덮는다. 하단 고정 버튼은 여백 확보 필수 |
| **모달 금지** | 안드로이드에서 모달은 별도 윈도우라 safe-area가 0으로 잡힌다 → 하단 시트는 오버레이로 |
| **키보드** | 입력창이 있는 하단 시트는 키보드가 버튼을 가리지 않는지 확인 |
| **글씨 배율** | 4단계(0.85 / 1.0 / 1.15 / **1.3배**). 최대 배율에서 카드·칩·탭이 깨지지 않아야 한다 |
| **한글 줄바꿈** | 「30초 동안 평소처럼 / 걸어주세요」처럼 어색하게 끊긴 사례가 있었다 |
| **작은 폰** | 세로 760px 미만 기기 대응 필요 |
