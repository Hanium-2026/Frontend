# 화면 재설계 — 정보 인벤토리

> 전면 재설계의 1단계. **API가 줄 수 있는 모든 정보를 나열하고 어느 화면에 놓을지 정한다.**
> 디자인(색·타이포)이 아니라 **정보 배치**가 이 문서의 주제다.
> 근거: 백엔드 컨트롤러·DTO 전수 대조 + 프론트 코드 실측

방향 3원칙은 `src/tokens.js` 상단 주석 참고 (무채색 지면 / 주인공 하나 / 크기로 위계).

## 0. 전제 — 상시 측정 앱이다

이 앱은 **사용자가 버튼을 눌러 30초 재는 앱이 아니다.** 백그라운드에서 하루 종일 IMU를 돌려
일상 보행을 모으는 것이 목표다(AGENTS.md '측정 방식' 참고). 화면은 이 전제로 설계한다.

**설계에 미치는 영향**

| 항목 | 세션 방식이라면 | 상시 측정이라면 |
|---|---|---|
| 홈의 성격 | 「측정 시작」이 주인공 | **자동으로 쌓인 결과를 보는 대시보드** |
| 주요 행동 | 측정 버튼 | 없음 — 확인이 주 목적 |
| 측정 화면 | 주 진입점 | **「지금 상태 확인」** 용도 |
| 데이터 부족 | 측정 실패 | **활동량 저하** — 그 자체로 의미 있는 정보 |
| 참고 모델 | Nike Run Club 류 | **Apple Health** |

⚠️ **현재 구현은 포그라운드 세션 방식**이다. 화면 설계는 목표를 따르되,
구현이 따라오기 전까지는 측정 진입점을 남겨둔다 — 단 **탭이 아니라 홈 카드 「지금 상태 보기」로만** 둔다.
탭은 자주 가는 곳이어야 하는데 상시 측정에서 측정 화면은 어쩌다 확인하는 곳이다(2026-08-20 결정).

## 2. 앱이 계산하고도 버리는 값

측정이 끝나면 로컬 `summary`에 14개 필드가 생기지만, `uploadAnalysis`는 8개만 보낸다.
**나머지는 결과 화면을 벗어나는 순간 사라진다.**

| 값 | 의미 | 전송 | 결과 |
|---|---|---|---|
| avgScore, minScore, maxScore | 점수 | ✅ | 기록에 남음 |
| riskLevel, dangerCount | 위험도 | ✅ | 기록에 남음 |
| symmetry → asymmetryScore | 좌우 대칭 | ✅ | 기록에 남음 |
| variability | 변동성 | ✅ | 기록에 남음 |
| **steps** | 걸음 수 | ❌ | **사라짐** |
| **distanceM** | 이동 거리 | ❌ | **사라짐** |
| **avgCadence** | 분당 걸음 | ❌ | **사라짐** |
| **suspectedRatio** | 이상 의심 비율 | ❌ | **사라짐** |
| **windows** | 분석 구간 수 | ❌ | **사라짐** |
| **lowConfidence** | 저신뢰 측정 | ❌ | **사라짐** |

측정 화면에서 걸음 수와 이동 거리를 실시간으로 보여주는데, **기록에서는 그날 몇 걸음 걸었는지 볼 수 없다.**

### 그런데 이 값들이 다 필요한가 — 따져본 결과

| 값 | 판정 | 근거 |
|---|---|---|
| **lowConfidence** | 🔴 **반드시 저장** | 아래 별도 항목 참고. 지금 데이터 품질을 망치고 있다 |
| **avgCadence** | 🟡 **저장 가치 있음** | 분당 걸음 수는 보행 속도의 대리 지표로, 파킨슨에서 특징적으로 변한다. 임상 근거가 확실하다. 단 **어르신 화면엔 불필요** — 보호자·의료진용 |
| **steps** | 🟢 측정 중에만 | 이 앱은 만보기가 아니다. 저장해봐야 «30초 측정 중 47걸음»이라 사용자에게 의미가 없다. 다만 측정 중에는 **«지금 제대로 세고 있다»는 피드백**으로 가치가 크다 |
| **distanceM** | ⚪ **빼도 된다** | 걸음 수 × 키로 추정한 보폭 = 추정의 추정. «약 35m»가 어르신에게 주는 정보가 없고 정확도도 낮다 |
| **suspectedRatio** | ⚪ **파생값** | `dangerCount / windows`와 같은 값이다. 둘 다 보내면 서버가 계산할 수 있으므로 따로 저장할 이유가 없다 |
| **windows** | 🟡 저장 가치 있음 | 그 자체로는 화면에 쓸 값이 아니지만 `lowConfidence` 판정의 근거이자 측정 품질의 척도 |

**결론** — 백엔드에 추가 요청할 것은 **`avgCadence`와 `windows` 둘뿐**이다.
`steps`는 측정 화면에만 두고, `distanceM`과 `suspectedRatio`는 화면에서도 뺀다.

### 🔴 lowConfidence를 안 보내는 것이 실제 문제를 만들고 있다

지금 코드는 저신뢰 측정일 때 `dangerCount`만 0으로 바꿔 보호자 알림을 막는다.
**그런데 `avgScore`는 그대로 보낸다.**

```js
dangerCount: lowConfidence ? 0 : summary.dangerCount,   // 알림은 막지만
avgScore: summary.avgScore,                              // 점수는 그대로 들어간다
```

즉 몇 걸음 걷다 만 측정의 점수가 **제대로 한 측정과 같은 무게로 일별 평균에 섞인다.**
실기기 기록 화면에서 `8/13 = 0점`, `8/11 = 99점`, 7일 평균 `49.5점`이 찍힌 것이 이 경우로 보인다.
0점이 실제 이상 보행인지 측정 실패인지 **데이터만 봐서는 구분할 수 없다.**

### 확정된 방침 — 걸음이 적으면 집계하지 않고 안내한다

**업로드하지 않는다.** 대신 화면에서 **더 걸으라고 안내**한다. 백엔드 변경도 필요 없다.

| 상황 | 처리 |
|---|---|
| 걷기 구간이 임계값 미달 | 분석을 업로드하지 않는다 (`uploadAnalysis` 생략) |
| 측정 화면 | **「조금 더 걸어야 기록돼요」** 실시간 안내 — 임계값에 도달하면 안내가 사라진다 |
| 종료를 누르면 | 「걸음이 적어 기록하지 않았어요. 조금 더 걸어보실래요?」 + 계속/종료 선택 |
| 기록·평균 | 애초에 올라가지 않으므로 오염되지 않는다 |

**«측정했는데 기록에 없다»는 혼란을 막는 방법은 배지가 아니라 사전 안내다.**
저장이 안 될 것임을 **저장 시점이 아니라 측정 중에** 알려주면 사용자가 스스로 조정한다.

⚠️ 지금은 짧은 측정에도 확인 팝업만 띄우고 **점수는 그대로 업로드**한다
(`dangerCount`만 0으로 바꿔 알림을 막는다). 이 부분을 위 방식으로 고쳐야 한다.

**상시 측정이 붙으면 이 문제는 대부분 사라진다.** 하루 종일 모으면 걸음이 부족한 날은 드물고,
그런 날은 «측정 실패»가 아니라 **활동량 저하**라는 유의미한 신호로 다뤄야 한다.

### 백엔드에 요청할 것 (2개)

1. `POST /gait/sessions/{id}/analysis`에 `avgCadence`(Float)·`windows`(Integer) 추가
   - `avgCadence`는 임상 지표, `windows`는 측정 품질의 원본 기록
2. 나머지는 요청하지 않는다 — `steps`·`distanceM`·`suspectedRatio`는 위 판정대로 불필요

## 4. 화면 통합 후보

### ① 측정 결과 + 세션 상세 → 하나로

거의 같은 정보를 보여주는 두 화면이다. **차이는 데이터 출처뿐.**

| `ElderResult` (측정 직후) | `SessionDetail` (기록에서 열람) |
|---|---|
| 로컬 `sessionStore` | 서버 `getSessionReport` |
| 평균·범위·대칭·변동성 | 평균·최저·최고·대칭·변동성 |
| + 케이던스, 이상 의심 비율, 분석 구간 | + 위험 횟수 |

같은 컴포넌트가 **출처만 다르게 받으면** 된다. 두 화면이 서로 다르게 보이던 문제도 함께 사라진다.
(2번의 (A)를 택하면 두 화면의 지표 목록이 완전히 같아진다.)

### ② 보호자 목록 + 연동 코드 → 하나로

`ElderCaregiverLink`는 전화번호 입력과 코드 표시뿐이다. 별도 화면일 필요가 없고,
보호자 목록 화면에서 **모달이나 하단 시트**로 처리하면 된다.

### ③ 측정 방법 안내 → 이용 가이드로 흡수

`ElderMeasureIntro`(주머니·걷기·점수)와 `ElderGuide`(측정·점수·기록·보호자)는 내용이 겹친다.
측정 안내를 **최초 1회만** 보여주기로 했으므로, 다시 보고 싶을 때 갈 곳은 이용 가이드면 충분하다.

⚠️ 인프라가 아직 없다(AGENTS.md 열린 작업) — 상시 측정 구현과 함께 만든다.

### WARD 홈 — 카드 구성

```
┌─ 헤더 (고정) ────────────── [긴급] ┐   ← SOS를 스크롤 밖으로
│  홍길동님, 안녕하세요               │
│  78 점               「안정」        │   ← 색 운반체는 칩 하나. 숫자는 T.ink
│  어제보다 3점 높아요                 │
├─ 카드 1 · 오늘 ────────────────────┤
│  보행 3번 · 점수 62~91              │   ← sessionCount, minScore, maxScore
├─ 카드 2 · 지난 7일 ────────────────┤
│  [차트]  평균 74점                  │   ← 빈 날은 빈칸으로
├─ 카드 3 · 보호자 ──────────────────┤
│  (현행 유지)                        │
├─ 지금 상태 보기 ───────────────────┤   ← CTA에서 강등
└────────────────────────────────────┘
```

**설계 근거**

| 결정 | 이유 |
|---|---|
| 측정 CTA 강등 | 상시 측정 홈은 대시보드다. 삼성헬스 홈에도 측정 CTA가 없다(레퍼런스 확인) |
| **점수 범위(min~max)** | 평균 하나로는 *가끔 나쁨*이 안 보인다. 평균 80·최저 45면 그게 신호인데 지금은 받아놓고 버린다 |
| 7일 평균 1회만 | 현재 헤더와 추이 카드에 **두 번** 나온다. 삼성헬스가 걸음 수를 두 번 보여주는 것과 같은 낭비 |
| 좌우 대칭·변동성 **제외** | 어르신이 「좌우 대칭 87%」로 취할 행동이 없다. 측정 결과·기록에만 둔다 |
| SOS 헤더 고정 | 위급할 때 스크롤해 찾는 건 이미 실패한 설계 |
| 카운트업 제거 | 1.1초간 숫자가 굴러가 값을 못 읽는다. 노년층 대상에서 확정을 늦출 이유가 없다 |

### 차트 — 막대에서 선으로 (`DailyTrend`)

일별 점수에 막대를 쓰지 않는다. 막대는 **0에서 자라는 크기**를 부호화하는데,
점수는 합산되는 양이 아니라 **0~100 척도 위의 위치**다(월 78 + 화 81 = 159는 의미가 없다).

| 문제 | 막대 | 선 |
|---|---|---|
| 실제 점수대(60~95)의 차이 | 0부터 그려 74와 81이 거의 같아 보인다. 바닥을 자르면 왜곡 | 위치 부호화라 구간만 그려도 정직 |
| 기록 없는 날 | 높이 0 막대 = 0점과 구분 불가 → 표시를 덧대야 함 | **선이 끊긴다** — 그 자체로 «없음» |
| 하루 안 변동 | 표현 못 함 | **min~max 밴드**로 함께 표현 |

**y축은 0~100 고정.** `riskTone`의 경계(70=주의, 50=위험)가 의미를 가지므로
데이터에 맞춰 축을 조이지 않는다 — 「78점」이 척도 어디쯤인지가 정보다. 70에 옅은 임계선을 둔다.

| 화면 | 형태 | 이유 |
|---|---|---|
| 홈 | 선 + 점 | 어르신 화면. 「오르내리는지」만 |
| 기록 | 선 + **범위 밴드** | 들여다보러 온 화면. 변동까지 읽을 맥락이 있다 |

**밴드가 임상적으로 핵심**이다 — 파킨슨·뇌졸중 보행은 평균이 떨어지기 전에 **흔들림이 먼저** 나타난다.
`minScore`·`maxScore`는 이미 받고 있으면서 쓰지 않던 값이다(1절 참고).

⚠️ 요일 라벨은 SVG `<Text>`가 아니라 RN `Text`로 그린다 — 전역 글씨 배율이 SVG엔 적용되지 않는다.
`BarChart`는 쓰는 곳이 없어져 삭제했다(git 히스토리에 남아 있다).

🐛 **함께 고칠 버그** — 현재 홈은 `trend[trend.length-1]`을 오늘 점수로 쓴다.
백엔드 `dailyScores`는 **데이터가 있는 날만** 주므로(빈 날 미채움), 오늘 안 걸었으면 **며칠 전 점수가 「오늘」로 표시**된다.
차트도 빈 날이 압축돼 월·수·금이 연속 3일처럼 그려진다.
→ 오늘 날짜와 대조해 없으면 `null`. (보호자 API는 `filter(d.date == today)`로 이미 이렇게 한다)
